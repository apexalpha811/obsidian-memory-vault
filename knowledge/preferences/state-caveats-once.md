# State a caveat once, then drop it

**Rule:** Raise an open item, risk, or caveat once. Then stop. Do not repeat it in later
turns because the user has not acted on it.

**Why:** Stated by the user after I flagged the same uncommitted-work item in three
consecutive messages. Re-raising an unactioned point reads as nagging, buries whatever is
genuinely new in that response, and implies the user missed it the first time. An item the
user has heard and not acted on is a decision they have made for now, not an oversight to
correct.

**How to apply:** Before appending a caveat or "open items" note, check whether it already
appeared earlier in the conversation. If it did, cut it. Applies to every recurring caveat:
uncommitted work, missing repos, unfilled placeholders, illustrative pricing, unverified
third-party claims. Genuinely new information about an old item is fine; restating the old
item is not.

Related: `close-every-job-explicitly.md` — close the job clearly, but closing does not mean
re-listing every caveat already given.
